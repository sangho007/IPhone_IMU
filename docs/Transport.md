# Transport.md 개요

`Transport.md`는 Telemetry 데이터를 전송하는 과정에서 필요한 네트워크, 프레이밍, 재시도 정책을 정리한 문서다. iOS 앱과 데스크톱 수신기 간에 USB 터널링(TCP)을 통해 protobuf 페이로드를 주고받는 시나리오를 가정한다.

## 핵심 내용 요약
- **전송 경로**: `iproxy`로 iOS 디바이스의 TCP 포트를 Mac `localhost`에 노출하고, 앱은 `127.0.0.1:4820`으로 접속한다.
- **페이로드 구조**: 4바이트 Big-Endian 길이 헤더 + protobuf 바이트 스트림. 길이 헤더 덕분에 스트림 파싱이 단순해진다.
- **직렬화 방식**: `TelemetryProtobufEncoder`가 DTO를 직접 protobuf wire format으로 변환해 외부 의존성을 줄인다.
- **재시도 정책**: 연결 실패 시 1.5초 간격으로 최대 5회 재시도하고, 전송 중 오류가 발생하면 연결을 닫고 루프를 재개한다.

## 운영 시 주의점
- ARKit/CoreMotion 데이터는 시뮬레이터에서 정상 동작하지 않으므로, 항상 실기기 환경에서 검증해야 한다.
- 수신 애플리케이션은 길이 헤더를 Big-Endian으로 읽고 동일한 protobuf 스키마에 맞춰 디코딩해야 한다.
- USB 연결이 끊기면 `iproxy` 세션이 종료되므로, 앱에서 연결 상태를 주기적으로 점검하거나 자동 재연결 로직을 운영한다.
